# Module 3: Physical Zero-Trust Hardware & The Two-Laptop Setup

## Why Do We Need Hardware At All?

Most software engineers ask:
> *"Why can't we just pop up a modal in the React web dashboard that says: 'Click Confirm to approve 250 bUSD'?"*

Here is the brutal cybersecurity truth:
If a hacker has compromised Laptop A, they can:
1. Hijack the React frontend and show you a fake screen that says *"Approve $10"*, while in the background submitting a transaction for **$10,000**.
2. Inject code into the browser process or operating system.
3. Hook system API calls or read clipboard memory.

This is why hardware security exists. In high-security banking, you don't approve multi-million-dollar wire transfers by clicking a webpage; you use a dedicated hardware security token (like a YubiKey or a Ledger).

### The Iron Rule of Machine Allocation
**Laptop A is treated as COMPROMISED.**
Laptop A holds the AI agent's session key (which has spending caps), but it **NEVER possesses**:
- The Owner master private key.
- The ESP32 supervisor hardware key.
- The 5 Guardian recovery private keys.

All cryptographic authority for overrides and blockchain state lives on **Laptop B**.

## 📟 The ESP32 Dedicated Hardware Signer

On Laptop B, we connect an **ESP32 microcontroller** with dedicated peripherals. It operates as an independent signing enclave.

### 1. The OLED Display #1 ("What You See Is What You Sign" — WYSIWYS)
- Connected directly via I2C (`GPIO 21 SDA`, `GPIO 22 SCL`).
- When an exception payment is requested, the ESP32 receives the raw EIP-712 payload.
- It parses the data itself and renders the exact recipient address (`0x00...cc`) and token amount (`250.00 bUSD`) on the OLED screen.
- **Why this matters:** Laptop A cannot trick the human by showing fake text in the browser. What appears on the hardware OLED is what the ESP32 signs!

### 2. The RC522 RFID Reader (Role Tiers)
- Connected via SPI (`SCK 18`, `MISO 19`, `MOSI 23`, `SS 5`, `RST 27`).
- We configure two physical cards:
  - **Junior Operator Card (`EE44651D`):** Grants permission for minor budget overrides up to $2,000 bUSD.
  - **Senior Admin Card (`331C4950`):** Grants permission for high-value overrides up to $10,000 bUSD and breach recovery resets.
- **Important Security Disclosure:** An RFID card UID alone is **NOT** strong cryptography (it can be cloned). In BASTION X, tapping the card merely selects the intended review tier. To move money, the smart contract still requires the cryptographic ECDSA signatures of both the ESP32 and the Owner!

### 3. The Physical Approval Button (GPIO 33)
- An approval cannot be generated by a software script or a fake network message.
- The operator must physically press and hold the tactile push button on `GPIO 33` for $\ge 1.5$ seconds.
- Only then does the ESP32 calculate the ECDSA signature over the EIP-712 hash.

### 4. The Emergency Panic Button (GPIO 32)
- Connected as an instant hardware interrupt (`INPUT_PULLUP`).
- If an operator notices a prompt injection attack, a physical intruder, or suspicious behavior, pressing **Button #1 (GPIO 32)** immediately triggers an emergency workflow:
  1. The ESP32 immediately refuses to sign any pending transactions.
  2. The ESP32 broadcasts a pre-signed `revokeSession` transaction over its independent Wi-Fi interface directly to the blockchain on Laptop B (`:8545`).
  3. This bypasses Laptop A completely! Even if Laptop A's backend is completely frozen, crashed, or malicious, the session is revoked on-chain.
  4. The ESP8266 remote node sounds a physical 5V active buzzer alarm and flashes an emergency LED.

## 🍯 Bonus: The Mirage Deception Honeypot

What if an attacker is logged in and snooping around our application?
If the system detects an attack (or if panic mode is activated), BASTION X engages the **Mirage Engine**:
- Instead of showing an error that tells the hacker *"You were caught"*, the system quietly switches to a synthetic sandbox.
- The hacker sees fake bank balances, synthetic customer names, and simulated transaction receipts.
- **Crucial Rule:** The Mirage sandbox is completely cut off from the real blockchain. Zero real funds can be moved while in Mirage mode.
